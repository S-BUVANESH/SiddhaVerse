## 2. Remaining Blockers

While the platform is ready for beta deployment, the following content gaps must be resolved for a full production release:

1. **Authentic English Translations**: All 1,000 verses currently have `english_translation: null`. Acquiring verified translations via licensing (e.g., B. Natarajan's translation) or professional translation commissions is the primary blocker for non-Tamil speakers.
2. **Tamil Morphological Disambiguation**: The suffix-stripping rules operate on romanized terms. Native Tamil text search is still purely lexical and lacks a sandhi splitter (word junction parser) to isolate root words in complex compound Tamil words (e.g., "சிவனுமாய்" → "சிவன்").
3. **Lexicon Scale**: The entity registry covers 93 entities. A full corpus representation requires expanding the entity definitions to 300+ medical terms, diagnostic procedures, and Siddhar classifications.

### AI Implementation Safeguards
During Phase 3, AI/LLM integration must be restricted to search augmentation and retrieval:

1. **Strictly Non-Generative**: LLMs must not be used to generate translations, expand descriptions, or write commentaries.
2. **Semantic Vector Search**: Vectorize the `search_text` and `tamil_text` fields using standard embedding models to support semantic queries (e.g., "rejuvenation methods" matching verses containing "kayakalpa").
3. **Hybrid Search Architecture**: Combine lexical matching (using the high-precision synonym and suffix maps developed in Phase 2B-4) with vector similarity. Lexical matches must be prioritised, with semantic search acting as a fallback for abstract queries.
