## 1. End-to-End RAG Workflow

The SiddhaVerse RAG workflow is a strict, linear pipeline designed to ensure that no statements are generated by the LLM without direct, verifiable support in the corpus.

## 2. Query Processing Layer

When a query is received, it is processed as follows:
1. **Tamil NFC Normalization**: Resolves accent decompositions.
2. **Tamil Suffix Stripping**: Converts inflected terms (e.g., `"pranayamam"`) to base stems (`"pranayama"`).
3. **English Synonym Expansion**: Converts English query terms to corresponding entities and Tamil transliterations (e.g., query `"breath"` expands to query `"breath practice_pranayama practice_kumbhaka"`).
4. **Metadata Extraction**: Identifies if the user specified a Siddhar name, plant name, or work (e.g., "Sivavakkiyar on mind" sets the SQL/Vector filter to `author = "Sivavakkiyar"`).

## 4. Prompt Engineering & System Instructions

The prompt template is designed to constrain the model's reasoning strictly to the provided context. The system instructions explicitly forbid speculation or external knowledge retrieval.

### Canonical Prompt Template:

```
You are the SiddhaVerse AI Scholarly Assistant, a factual repository search assistant.
Your goal is to answer the user's query using ONLY the verified context documents provided below.

=== STRICT RULES ===
1. Answer the query using ONLY the facts explicitly mentioned in the [CONTEXT] block.
2. Do not use any external historical, religious, or medical knowledge.
3. If the context does not contain sufficient information to answer the query, state: "The SiddhaVerse corpus does not contain evidence to answer this query."
4. Every fact you state must be cited inline using the format: <cite doc="document_id" hash="content_hash" />. Place the tag immediately after the sentence containing the cited fact.
5. Do not write a summary bibliography at the end; place citations inline.

=== CONTEXT ===
{formatted_context}

=== USER QUERY ===
{user_query}

=== VERIFIED RESPONSE ===
```

## 5. Post-Generation Citation Verification

To prevent LLM hallucination of citations, the backend intercepts the raw output of the LLM and runs a programmatic verification script:

```python
import re

def verify_citations(llm_output, injected_contexts):
    # Context maps document_id -> expected_hash
    context_map = {c["document_id"]: c["content_hash"] for c in injected_contexts}
    verified_citations = []
    
    # Regex to find <cite doc="..." hash="..." />
    citations = re.findall(r'<cite doc="([^"]+)" hash="([^"]+)"\s*/>', llm_output)
    
    for doc_id, val_hash in citations:
        if doc_id not in context_map:
            # LLM hallucinated a document not injected into context!
            return False, "Security Error: Hallucinated document citation detected."
        if context_map[doc_id] != val_hash:
            # LLM hallucinated a hash or mismatched the document!
            return False, "Security Error: Mismatched content hash detected."
        verified_citations.append(doc_id)
        
    return True, verified_citations
```

### Fallback Actions:
- **Success**: The tags are converted to interactive UI citation links, and the response is served.
- **Verification Failure**: The system discards the response, logs a warning, and outputs: *"The assistant generated an unverified response. Result blocked for scholarly integrity."*
